E2E Analytics

An end-to-end SQL and Power BI project that asks one question: why does a quick-commerce network in Chennai miss its ten-minute promise? 1.2 million orders, 24 dark stores.

The business problem.

Ten Minute Promise is a fictional grocery delivery company. Its brand rests on speed, yet customer ratings fall sharply once a delivery crosses 15 minutes. Operations has no single view of why.

What we ask

Which stores, hours and zones miss the promise, and what do those misses cost in refunds and lost repeat orders?

Who uses it

City operations heads who staff stores, and store managers who plan shifts each morning.

What they decide

Where to add riders, which stores to re-stock earlier, and which zones need a new dark store.

The dataset is synthetic and was generated with a Python script that mimics realistic order patterns. Figures on this page are sample outputs, so replace them with your own query results.

From raw files to a report.

The pipeline stays simple on purpose. Every step can be re-run, so anyone on the team can rebuild the report from scratch.

  1. GeneratePython creates six CSV files with orders, riders, stores and customers.
  2. LoadFiles go into SQL Server staging tables with BULK INSERT.
  3. CleanSQL removes duplicates, fixes nulls and flags impossible timestamps.
  4. ModelClean data becomes a star schema of facts and dimensions.
  5. AnalyseViews hold KPIs built with CTEs and window functions.
  6. ReportPower BI connects to the views and publishes four pages.

A star schema that stays readable.

One fact table at the centre, five dimensions around it. Power BI filters flow from the dimensions into the fact table, which keeps DAX short.

A sixth table, dim_product, links to the fact table the same way and is left out of the sketch for space.

The SQL behind it.

Three short queries do most of the work: cleaning, a delivery-time view and a ranking that flags the worst hours.



Written for SQL Server. For MySQL or PostgreSQL, swap DATEDIFF and TOP for the equivalent functions.

Stores the raw and clean data. T-SQL handles cleaning, views, CTEs and window functions. SSMS is the editor.

How it works.


Tap a step to see what happens inside it.




A Python script with a fixed random seed writes six CSV files. It builds in real patterns, such as a 7 pm rush and slower rides in heavy rain, so the analysis has something true to find.


BULK INSERT copies each file into a staging schema without changing it. Row counts are compared with the CSV files, so nothing goes missing silently.


Queries remove duplicate orders, fill empty ratings and flag impossible timestamps. The clean rows then become one fact table and five dimension tables, linked by keys.


Power BI connects to the SQL views in Import mode. You set the relationships, add a date table and write the DAX measures once. Every visual reuses them.


Slicers and drill-through let a manager go from a zone to a single store. The report is published, and each finding ends in a clear recommendation such as adding evening riders.
